# Done list — slice-5 (written BEFORE dispatch; does not grow during it)
Base bytes: the commit recorded by `charter gate slice-5 --dispatch`
Scope: G-MEASURED and completion criteria 4 and 10. `holden-ledger` is an append-only signed ledger. Controls are sealed known-broken and known-good variants. Each check, lens and cognition gets a catch rate and a false-pass rate with Wilson bounds, and authority is taken from the pessimistic bound. Feedback into lens draw weights and re-plan triggers is fed by real ledger data. The MCP server gains the `telemetry` tool.
Proofs:
1. P1 append-only-ledger: SQLite in the private-root `db/`. Each record is chained by SHA-256 of the previous record and signed with Ed25519. Any edit, deletion or reorder of past records is detected by `holden ledger verify` and the record is named. Appends do not re-verify the whole chain: they check only the tip, and full verification is a separate command.
   - Reopen: on both OSes, run the tests and `holden ledger verify` on a produced ledger.
   - Fail-without mutant: drop the previous-hash link. The test `tampered_history_is_detected` must fail.
   - Test: `holden-ledger::tests::{tampered_history_is_detected, append_checks_tip_only}`
2. P2 controls-measure-catch-rate: for each holdout version, sealed control variants are run through the real evaluator:
   - known-broken mutants, generated by the plan's targeted broken variant and by fixture mutants, including the S-RUNNER never-again defects;
   - known-good builds.
   The ledger records a catch rate (broken variants failed) and a false-fail rate (good builds failed) per check, per lens concept and per cognition, with Wilson 95% bounds. The numbers are computed from real runs of the fixture product.
   - Reopen: run the control suite on the fixture and compare the recorded counts with a rerun.
   - Fail-without mutant: count controls without running them, for example by assuming "broken ⇒ fail". The test `catch_rate_from_real_runs` must fail.
   - Test: `holden-ledger::tests::{catch_rate_from_real_runs, wilson_bounds_correct, per_lens_and_cognition_rates}`
3. P3 authority-from-pessimistic-bound: each check's authority is computed only from its measured Wilson bounds against owner-set bars stored in sealed config. The levels are advise, recommend and block. A block requires lower-bound catch ≥ bar AND upper-bound false-fail ≤ bar. An unmeasured or under-sampled check is advise-only. A verdict's merge-blocking power is the minimum authority across the checks that decided it.
   - Reopen: run the tests.
   - Fail-without mutant: use the point estimate instead of the bound. The test `authority_uses_pessimistic_bound` must fail.
   - Test: `holden-ledger::tests::{authority_uses_pessimistic_bound, unmeasured_check_is_advisory_only}`
4. P4 feedback-loops: ledger telemetry changes future behaviour in three deterministic, tested ways:
   - (a) Lens draw weights are recomputed from per-lens yield, and the next keyed draw uses them. Low-yield lenses are demoted but never zeroed, so they are never permanently invisible.
   - (b) Re-plan triggers fire on a canary leak, on vacuity (a pass on a do-nothing product), and on proven false results. A trigger produces a re-plan item and bumps the holdout version.
   - (c) The telemetry MCP tool reports these metrics with sample sizes.
   - Reopen: run the tests. Run the fixture loop twice and show the weights and the draw change between rounds.
   - Fail-without mutant: ignore the weights in the draw. The test `draw_uses_ledger_weights` must fail.
   - Test: `holden-ledger::tests::{draw_uses_ledger_weights, vacuity_triggers_replan, telemetry_reports_sample_sizes}`
5. P5 self-test: holden runs its own controls against its own code. Fixture mutants of `holden-seal`, `holden-mcp` and `holden-eval` reintroduce known defects:
   - the env reaching an elevated process;
